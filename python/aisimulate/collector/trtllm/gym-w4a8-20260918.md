## Controlled ablations and regressions

- Mapping plus W4A8 data, keeping the original Python-sampled request vectors:
  GPT-OSS/B200 TPOT MAPE **168.7816% -> 5.3295%**; TRT TPOT **36.1916%**.
  All **232 points outside GPT-OSS/B200 remain bit-identical** in TTFT/TPOT.
- Correcting the sampler separately yields TRT TPOT **36.2472%** and SGLang
  TPOT **12.5170%**. Every generated request length was checked against NumPy's
  client contract. This is workload alignment, not an accuracy tuning step.
- All 31 GPT-OSS/B200 TPOT APEs improve; final range **0.23%–17.38%**.
  **15/31 TTFT APEs worsen** despite mean TTFT improvement. Config155,
  ISL1024/concurrency4, worsens **5.97% -> 65.78%**. Correct activation precision
  removes an accidental compensation; TTFT scheduling/overhead remains open.
- Across the full cohort, **117 TTFT and 46 TPOT** APEs worsen by more than
  **0.1 percentage point**, including the separately changed request sampling.
  This reporting threshold is not an acceptance gate. The largest TPOT
  regression is config1553/B200/ISL8192/C1024: **182.20% -> 185.91%**.
- Residual TRT TPOT MAPE: DeepSeek B200 **49.18%**, MiniMax B200 **39.40%**,
  MiniMax B300 **44.15%**, Qwen B200 **85.39%**. This fixes the confirmed
  GPT-OSS precision defect; it does not establish full accuracy for other models.
- The reproduced config131/C256/ISL1024 predicts **17.1702 ms** TPOT versus
  historical **16.7921 ms** (2.25% APE), and fresh uninstrumented serving
  **16.5492 ms** (3.75% APE). These are distinct reference observations.
