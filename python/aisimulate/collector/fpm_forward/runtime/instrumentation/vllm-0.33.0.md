These cases stay unsupported. The adapter reports them by name and never relabels them:

- `ChunkedLocalAttentionSpec`.
- `RSWASpec`. Its [manager](https://github.com/vllm-project/vllm/blob/4ba787ec9959e566d3b587a796dff07673324da5/vllm/v1/core/single_type_kv_cache_manager.py#L900-L943) frees the blocks between the prompt and the decode window, and no cache kind models that.
- `HiSparseHotSpec` and `HiSparseResidentSpec`.
- `EncoderOnlyAttentionSpec` and `CrossAttentionSpec`.
- Any other spec class.
- A uniform group whose inner specs map to different kinds.
- HiSparse placement. A group with `host_resident` true, a role other than `DEFAULT` or `enable_kv_transfer` false leaves the cache unresolved. So does a host-resident tensor. One device pool is modeled.

This pin rejects speculative groups and unsupported alias layouts. Runtime source checks include the selected backend module. To select another backend, audit and declare its implementation. Do not claim that these inspected backends cover it. A vendor patch that changes a declared file produces unresolved evidence with the actual hash retained. After you inspect such a patch, update the source notes, mapping tests and manifest in a fresh campaign attempt.

The vLLM hashes are the files of tag `v0.33.0`. They equal the installed files of the PyPI wheel `vllm-0.33.0-cp38-abi3-manylinux_2_28_aarch64.whl` (sha256 `e9e404f52c8494b69bd83fe99fe7ecfa9f6b89fbd156d2a9639c24ea41d6d606`). `vllm/_version.py` is not in git; its hash comes from that wheel, and it names version `0.33.0` and commit `g4ba787ec9`. The Dynamo scheduler hash is the file `components/src/dynamo/vllm/instrumented_scheduler.py` at `9abd2ef0d908c4bb323e1b8956ea76a5772a1d41`, installed as `dynamo/vllm/instrumented_scheduler.py`. The probe loads this bundle in the runtime image and still checks every declared hash against the installed file, so a runtime with another scheduler file leaves the evidence unresolved.

`fpm_exec.sh` starts `etcd` on rank 0. If the runtime image has no `etcd`, mount a static `etcd` binary, for example at `/usr/local/bin/etcd`. If the image does not hold the pinned Dynamo packages, mount them and put the container path of that mount on `PYTHONPATH` in the environment of the probe command. The runner passes that environment to `srun`, Pyxis passes it into the container, and the probe setup keeps it after the staged bundle.
