`SlidingWindowSpec.extra_retained_tokens` is present at this revision and extends retained history for speculative prefill. The adapter requires the actual integer value zero; an absent or nonzero value remains unresolved. Page sizing changed from 0.27, so this adapter reads the actual `page_size_bytes` property and rejects compressed `storage_block_size` instead of applying an older formula.

Both pins reject attention chunk retention, speculative groups, unknown cache spec classes and unsupported alias layouts. Runtime source checks include the selected backend module; selecting another backend requires auditing and declaring that implementation rather than claiming that these inspected backends cover it. A vendor patch changing a declared file produces unresolved evidence with the actual hash retained. Update source notes, mapping tests and the manifest in a fresh campaign attempt after inspecting such a patch.

This example was source-audited against the ARM64 Dynamo 1.5.0 image `nvcr.io/nvidia/ai-dynamo/vllm-runtime@sha256:93506f88fc21e74aa2611fedf1ac8077040dab509e1861a62bb24390aea463c0`. The relevant installed source files matched the pinned upstream sources. The generated vLLM build identifier was `g2cf0a6915`. This identifies the inspected source build; live verification remains a per-campaign requirement.
